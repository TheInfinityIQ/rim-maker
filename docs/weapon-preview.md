# Reusable weapon preview

Combat → Verbs embeds `src/components/weapon-preview/WeaponPreview.vue`. It receives the same reactive `WeaponRanged` object as the form, so Total range, uploaded weapon texture, and sound choices drive the preview directly. PrimeVue supplies buttons, tags, and messages; application CSS handles layout and the map.

## Raid village and positioning

The scene uses a settlement generated by RimWorld's own `BaseGen` settlement rules, including buildings, crops, paths, and defenses. Its background is captured once in the installed game. The browser composes that background with a separate rendered colonist, the current weapon texture, and a live tile-edge range outline. It does not run a copy of RimWorld in the browser or generate a new village on every page load.

The initial colonist position is exactly **100 tile centers west of the highlighted outermost western sandbag**. Both coordinates and the native map's blocked cells are recorded in `firing-range.json`. The distance is checked by unit and browser tests.

- Drag the colonist to relocate him. The outline follows during the drag; an invalid drop returns to the previous valid position.
- Pick up colonist also supports click/tap-to-place on open ground. Buildings and out-of-map locations reject drops.
- Reset position restores the original 100-tile position and initial camera. It does not reset weapon settings or uploaded media.
- Drag the ground to pan, click ground to aim, and use arrow keys to move the selected colonist or target. Shift moves five tiles; Escape cancels placement.
- Fit weapon range centers on the colonist. Village overview shows the approach; View village zooms toward the settlement.

Markers stay legible at distant zoom levels; their tile coordinates determine distances. Minimum range is outlined when present in the weapon model.

## Reference media and export defaults

New weapons use the game's assault-rifle texture, `Shot_AssaultRifle`, `GunTail_Medium`, and `Interact_Rifle` until changed. The game definition references are also the defaults in the exported mod. The website's reference samples are **not included in exported ZIPs**. Uploaded replacements are exported normally.

The preview includes a small set of reference media: the generated village image, the game-rendered colonist, the assault-rifle texture, and three assault-rifle sound samples. The website's Ludeon attribution applies to these files. `public/previews/reference-audio.json` records the original resource paths and sample hashes. Game assemblies are not distributed.

Uploaded weapon images replace the equipped texture and thumbnail immediately. Use assault rifle restores the built-in texture. Uploaded firing, tail, and interaction audio can be auditioned through Test fire and Handle weapon; removing an upload restores the corresponding assault-rifle reference. Another selected game SoundDef without a bundled sample is preserved for export and clearly requires an uploaded clip for browser audition.

Audio uses a user-initiated Web Audio context, current burst spacing, and a separate tail sample. Stop sound, position reset, switching away from a cached weapon, or unloading the component cancels playback. Replaced/unmounted upload object URLs are revoked. Very large bursts schedule at most twenty shots within ten seconds; clips and tails can finish afterward. This is a sound audition, not a full reproduction of SoundDef pitch, environmental reverb, or the combat simulation.

## Reuse

`target-change` and `colonist-change` emit positional information. The `scene-overlay`, `controls`, and `footer` slots expose target, colonist, and reach state; the overlay also receives the visible extent. Future projectile renderers can share the scene without duplicating the forms or media lifecycle. Preview state is separate from export data.

Range cells match the installed game's float-based `GenRadial` rule. Ten recorded radii, including 15.9, 33.5, and 79 tiles, are checked against values exported by the running game. The website extends the same geometry to 200 tiles; larger values retain distance checks but omit the expensive outline. The captured map spans approximately 224 tiles.

The placement/range image does not simulate cover, line of sight, damage, or accuracy. A range result alone does not guarantee a successful shot. The **Shooting example** section supplies native game recordings and a local companion for recording the edited weapon using the actual engine; see [native shooting preview](native-shooting-preview.md). Runtime behavior is also tested by the separate in-game suite.

## Regenerating reference media locally

With RimWorld closed, run:

```sh
npm run capture:range-preview
```

The helper compiles `tools/rimworld/RangePreviewCapture.cs` against installed assemblies, builds a temporary Core-only profile and mod, generates the settlement, and renders the scene and sprites. Results, calibration, blocked cells, and a log go under ignored `game-test-results/range-capture-*`. The temporary mod is removed. A game window can appear while rendering. `npm run capture:range-preview -- --compile-only` validates the helper without launching or affecting a running game.

Prepare the three reference sounds independently, without launching the game:

```sh
python scripts/extract-preview-audio.py --game "path/to/RimWorld"
```

This requires UnityPy in the local Python environment (or the local `.rimmaker-tools/python` installation). It reads only the selected sound resources from the installed game and writes decoded WAV samples and provenance under ignored `game-test-results/reference-audio`. It does not modify game files.

Inspect generated results before replacing public media and calibration; these preparation commands do not overwrite website assets automatically. Browser checks cover dragging, keyboard/touch placement, reset, blocked drops, reactive range, decoded sound playback, bad-audio errors, custom media, and restoring defaults. Halo browser cases independently compare the exported XML and uploaded bytes.
